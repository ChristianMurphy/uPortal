# Handoff: web components in English, Spanish, French and other languages

The work for MOD-D50 (web components come in English, Spanish and French) and MOD-D51 (a site
adds a language with a bundle and a `portal_locales` entry), with MOD-I231, MOD-I232 and
MOD-I235. The guide's "Adding a language" section and its notes on messages describe the result
(`docs/developer/web-components/README.md`).

Branches: `ccr-43ba0785-hzlrj5-i18n` in uPortal and in uPortal-start, both from
`ccr-43ba0785-hzlrj5`. Under MOD-D53 this branch also adds the D50 and D51 text for each
component that lands without it. `translations.unit.test.ts` lists the keys that are missing.
The last merges of the integration branch took uPortal `1b535ee` (which brought in
`up-background-preference`, whose keys already had es and fr text) and uPortal-start `ad95212`.

## Proposed LOG rows (MOD-I260 to MOD-I269)

* MOD-I260: `MessagesRESTController` read `locale=zh_TW` (Java's and `portal_locales`' form) as
  no language and used the user's locale instead. Fixed in `2b5b5b0`.
* MOD-I261: in Bootstrap 6 alpha a select's arrow sits at the physical right but its padding at
  the inline end. In a right-to-left locale the arrow covers the value. Fixed in the shared sheet
  (`c782b7b`). Bootstrap may want the same fix.
* MOD-I263: the English page info said "of 1 items" for one item, as 5.17 did. Fixed in
  `72a9b8f`, with the characterisation spec in uPortal-start `17a060a`.

## Running it locally

* uPortal: `./gradlew --no-parallel install -x test -x javadoc`, retried when Maven Central
  answers 429.
* uPortal-start: `JAVA_HOME` on a JDK 11, then `portalInit` and `tomcatStart`. The i18n specs are
  `tests/i18n` and `tests/ux/i18n`. `web-components-locale.spec.ts` imports its own
  `e2e-locale` account, so it never changes a shared user's locale.
* The Chromium here is older than CI's. A check on computed styles must accept both ways of
  writing a value.
